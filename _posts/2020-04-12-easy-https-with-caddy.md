<p><a href="https://letsencrypt.org">Let's Encrypt</a> has made obtaining SSL certificates very affordable (free!). Setting up the HTTPs server with Nginx proxy and <a href="https://certbot.eff.org">certbot</a> is still not quite straightforward. </p><p>There are multiple steps and proofs via ACME protocol that needs to be done right and not easily automated. Besides one time setup, we also needed to make sure the certs are correctly renewed at a regular interval. Then we also need to make sure to set up HTTP to HTTPS redirects and make sure we configure SSL correctly.</p><p>I have written about that before. It is not hard but not quite simple as I'd hope for the world that is seemingly HTTPs by default today.</p><figure class="kg-card kg-bookmark-card"><a class="kg-bookmark-container" href="/using-let-s-encrypt-with-nginx-centos-7/"><div class="kg-bookmark-content"><div class="kg-bookmark-title">Using Let’s Encrypt with Nginx CentOS 7</div><div class="kg-bookmark-description">This is to recap the steps outlined in this digital ocean’s post</div><div class="kg-bookmark-metadata"><img class="kg-bookmark-icon" src="/favicon.ico" alt=""><span class="kg-bookmark-author">Minimal Engineering</span><span class="kg-bookmark-publisher">Varokas Panusuwan</span></div></div></a></figure><h3 id="enters-caddy">Enters Caddy</h3><p>The premise of Caddy <a href="https://caddyserver.com/docs/automatic-https">automatic HTTPS</a> simple. The whole ACME protocol negotiation and cert renew is done entirely in server. There is no need for a separate scripts or scheduler to handle any of the above</p><p>That is done via a very simple <code>Caddyfile</code> which could be readily understood. </p><h3 id="using-caddy-as-a-https-proxy">Using Caddy as a HTTPS Proxy</h3><p>Three simple parts.</p><p><strong>Caddyfile</strong> – This is the configuration. If the first line is a domain name, Caddy assumes you'd want to set it up as HTTPs. The next line is where it should proxy the website </p><p><strong>docker-compose.yml </strong>– Assuming we already run other services as Docker, we'd want to compose it with other servers. </p><p>⚠️ Caddy needs a persistent datastore to save the downloaded certificates. We'd always want to map <code>/data</code> into the host path. If Caddy loses this data, it will repeatedly call to Let's Encrypt every time we restart the server, and we may get rate-limited for a few days.  </p><!--kg-card-begin: html--><script src="https://gist.github.com/varokas/28fcce848858701905a6dfeeb241f647.js"></script><!--kg-card-end: html--><p><strong>Allow SSL Traffic in Firewall</strong></p><p>This depends on our infrastructure. Cloud Providers nowadays provided image with no software firewall (e.g. <code>ufw</code>) but rely on networking configuration in the cloud instead. </p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="/assets/images/ghost/2020/04/Screen-Shot-2020-04-12-at-1.40.55-PM.png" class="kg-image" alt loading="lazy"><figcaption>Allow HTTPS in AWS Lightsail network configuration</figcaption></figure>
